# 项目架构

## 组件边界

- ESP32-S3 采集和播放音频，在本地检测唤醒词并决定音频去向；它不承担房间混音。
- 灵矽提供语音识别、智能体语义理解、MCP 工具调用和语音回复。
- Go 后端维护好友、配对口令、房间、邀请确认和在线状态。
- Janus Gateway AudioBridge 在服务端处理 WebRTC 实时音频和房间混音。

## 麦克风音频路由

设备本地维护短时音频缓冲和唤醒词检测：检测到唤醒词后丢弃缓冲中包含唤醒词的片段，将后续指令音频交给灵矽；未检测到唤醒词时，将缓冲音频送入对讲房间。缓存时长及切换策略需要在目标开发板上实测，以平衡唤醒词泄漏风险和对讲延迟。

## 首个验证顺序

1. ESP32-S3 开发板连接灵矽并完成语音问答。
2. 本地唤醒词检测和音频路由验证。
3. 单设备连接 Janus AudioBridge，验证 WebRTC 音频。
4. 并行运行唤醒检测、灵矽控制和对讲媒体。
5. 加入好友、邀请确认和成员查询业务。

各阶段记录实测板型、PSRAM、内存余量、音频参数和日志，稳定后再固化硬件选型。
