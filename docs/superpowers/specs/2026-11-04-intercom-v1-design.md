# 灵矽对讲机 v1 架构设计

## 目标与范围

ESP32-S3 对讲机通过语音创建房间、添加好友、邀请在线好友并查询在线成员。手机仅用于首次 Wi-Fi 配置；日常交互不依赖页面。灵矽负责语音识别、语义理解和语音回复，Go 服务负责账号、好友、房间和会话业务，Janus AudioBridge 负责房间混音。

v1 硬件基线为带 PSRAM 的 ESP32-S3、I2S 麦克风和音频 Codec，具体型号后续实测。配网使用设备临时热点和本地网页，扫描结果以 Wi-Fi 名称列表呈现，用户选择网络并输入密码。

## 组件与音频路由

- ESP32 采集/播放音频，并通过一条持久双向 WebSocket 与 Go 服务交换音频帧和控制事件。
- Go 服务对每台 ESP32 提供独立的实时媒体会话，并作为服务器端虚拟灵矽设备连接灵矽 WebSocket。虚拟设备身份、灵矽会话和对话上下文按物理设备隔离。
- Go 服务运行短时音频缓冲和唤醒词检测。普通语音上行到 Janus；唤醒后暂停 Janus 麦克风上行，把后续指令音频发给灵矽。
- 普通对讲时，Janus 混音经服务器媒体端点返回 ESP32；控制模式时，灵矽 TTS 音频经服务器下发。服务器按会话模式选择下行来源，避免两路音频同时播放。
- 房间、好友和在线状态工具由 Go 服务实现，并通过灵矽云端 MCP 暴露给智能体。好友通过面对面交换一次性语音配对码并由双方确认；只允许邀请在线设备。

音频路由概览：

```text
上行：ESP32 -> Go 音频入口 -> 唤醒检测
  普通语音 -> Go WebRTC 媒体端点 -> Janus AudioBridge
  唤醒后指令 -> 对应设备的虚拟灵矽 WebSocket

下行：Janus 房间混音 -> Go 媒体端点 --普通对讲--> Go -> ESP32 -> 扬声器
      灵矽 TTS                    --控制模式--> Go -> ESP32 -> 扬声器
```

## 身份、断线与重连

- 一台物理 ESP32 对应一个用户身份和一个虚拟灵矽设备；首次语音使用时创建用户身份。
- 虚拟设备的注册/绑定身份稳定，运行中的灵矽、Janus 会话独立于其他设备。
- ESP32 短暂断联后，服务器保留运行会话 60 秒作为初始宽限期；宽限期内使用相同设备身份重连并恢复会话。重连时丢弃断联期间积压的音频。
- 超过宽限期后释放灵矽连接、Janus 媒体会话和临时音频缓冲，但保留设备身份及用户/好友/房间持久数据。
- 邀请目标离线时立即返回失败，不暂存邀请。

## 配网与安全边界

设备首次启动提供临时热点和本地配网页。操作系统 captive portal 自动弹出作为便利能力，仍需支持用户手动打开本地地址。Wi-Fi 密码仅在设备配网流程使用，不进入仓库或普通日志。设备到 Go 的 WebSocket 使用设备身份鉴权；虚拟灵矽凭据保存在服务端配置/密钥管理中，不下发到 ESP32。

## 主要验证关口

1. 用 Linux 虚拟客户端验证灵矽是否允许服务器端设备身份完成注册/绑定、OTA 鉴权和 WebSocket 音频会话；每台模拟设备必须有独立身份和会话。
2. 验证服务器媒体端点能把实时音频发布到 Janus AudioBridge，并将房间混音下行到 ESP32 客户端。
3. 在目标板上测量连续采集、WebSocket 音频传输、播放和唤醒路由的内存、延迟及断网恢复表现。
4. 实测唤醒误触发、指令切分、控制模式扬声器静音房间下行，以及恢复房间音频时的缓冲清理。

## 未决实现值

- 60 秒断线宽限期是 v1 初始值，应依据弱网重连体验和服务端资源占用调整。
- 灵矽平台对服务器生成/持有的虚拟设备身份是否允许注册绑定，须通过账户实测确认；失败时先完成 Janus 与设备 WebSocket 路由，灵矽会话作为独立集成关口处理。
- 唤醒词模型、音频编码/帧时长、设备到 Go WebSocket 的具体帧封装和 WebRTC 媒体端点技术选型在实现计划中确定，并以端到端验证为准。
